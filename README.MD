How everything connects — plain English
iam-readonly-role.yaml is what the customer runs in their own AWS account — once, ever. It creates a role that says "I trust your platform to look at my billing, but only read, never write." Your platform's account ID and a secret UUID (ExternalId) are baked into this role.
ingestion.py is your data collector. Every hour it wakes up, calls AWS STS with the customer's role ARN and their ExternalId, gets temporary 1-hour credentials, calls Cost Explorer, pulls 32 days of costs, normalizes the messy AWS service names into clean groups, and upserts everything into Postgres. The ON CONFLICT in the upsert means running it twice never creates duplicate rows.
schema.sql is your database structure. Six tables: tenants (companies using your platform), users (their logins), aws_accounts (their connected AWS accounts with role ARNs), cost_records (the actual billing data — your highest-volume table), budgets (spending limits), and alert_events (every alert that ever fired). Three views are pre-built for the most common dashboard queries.
main.py is your API. FastAPI gives you automatic docs at /docs. It handles user registration/login with JWT, connecting AWS accounts, and serving all the cost data the dashboard needs — daily totals, service breakdown, region breakdown, budgets, alerts. When a customer connects an account, it immediately triggers a background sync.
.env.example — copy to .env, fill in 4 values to start: PLATFORM_AWS_ACCOUNT_ID, DB_URL, TEST_ROLE_ARN, TEST_EXTERNAL_ID. Everything else can wait.
requirements.txt — one command: pip install -r requirements.txt
